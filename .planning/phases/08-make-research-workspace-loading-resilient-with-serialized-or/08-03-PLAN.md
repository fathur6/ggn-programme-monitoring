<interfaces>
Existing client contracts to extend, not replace:
- `openProgramme(prog)` sets `currentProgramme`, resets workspace selection/dirty state, and calls `loadResearchWorkspace()`.
- Current initial read capabilities are profile, PEOs, PLOs, references, mappings, coverage, and review; existing targeted loaders remain available for retries and refresh actions.
- `researchFailure(error)` is used by mutation paths and must continue to set mutation error/dirty state; read endpoint failures must use separate endpoint-keyed state so a failed read does not mark unsaved edits dirty.
- Assessment loading currently starts on the assessment tab and chains mapping then review; Phase 8 must replace that dependency chain with the aggregate assessment envelope while retaining existing `assessmentMapping`, `assessmentReview`, `assessmentSaveState`, and review semantics.
- The lazy boundary is exact: `loadResearchWorkspace()` calls only `getResearchWorkspaceApi(programmeId)` and never claims to return assessment data; assessment-tab activation calls `getAssessmentWorkspaceApi(programmeId)` once for mapping and review.
- `google.script.run` uses fluent `withSuccessHandler`/`withFailureHandler` callbacks and may complete calls out of order.
</interfaces>

Resolved choices from research: use one aggregate initial research call and one aggregate assessment call only on assessment-tab activation, with existing public endpoint calls reserved for targeted retries. A local retry button may replay a read request, but never silently replay a save/reset mutation. Keep `researchError` for mutation/fatal compatibility where needed while endpoint-keyed state drives workspace read presentation.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Apps Script aggregate response → Vue state | Endpoint envelopes contain untrusted/failed data that must be attributed before commit. |
| User programme switch → asynchronous callbacks | Older programme/load generations can complete after a new programme is selected. |
| UI retry action → Apps Script RPC | Endpoint selector and programme identity must map only to authorized read calls. |
| Vue mutation controls → Apps Script writes | Save/reset operations must remain distinct from replayable read retries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-10 | Tampering | Vue generation-guarded commit | high | mitigate | Capture generation and canonical programme identity for each workspace read; ignore stale callbacks before any state write. |
| T-08-11 | Information disclosure | Endpoint error UI/logs | medium | mitigate | Render safe endpoint code/message, keep diagnostics separate, and avoid displaying server Sheet/schema details. |
| T-08-12 | Elevation of privilege | Targeted retry selector | high | mitigate | Allowlist endpoint-to-existing-wrapper mappings and pass the captured canonical programme ID; server authorization remains authoritative. |
| T-08-13 | Tampering | Read retry versus mutation replay | high | mitigate | Test that retry actions call only read RPCs; retain existing save/reset methods and canonical post-save behavior. |
| T-08-14 | Denial of service | UI aggregate/retry loading state | medium | mitigate | Track endpoint loading independently, avoid duplicate retries for the same generation, and preserve successful panels while one capability is busy. |
| T-08-SC | Tampering | Package-manager installs | low | accept | No package install is planned; client tests use existing Node built-ins and platform RPC doubles. |
</threat_model>
